# Reconstructed OMOP SQL

**These queries were newly written in 2026 for this demonstration. They are not the original WashU Databricks queries, which are unavailable.** They follow public OMOP CDM v5.4 conventions and contain no institution-specific schema, catalog, or table names.

All five files run, in order, against the synthetic OMOP tables generated by `omop_mdd.synthetic`. `tests/test_sql.py` executes them in DuckDB and checks the results.

| File | Creates | What it does |
|---|---|---|
| `01_case_cohort.sql` | `case_cohort` | Persons with a condition in the `depressive_disorder` concept set or its descendants. Index date = first such condition. Age at index within bounds. |
| `02_comparison_cohort.sql` | `comparison_cohort` | Persons with no condition in the `comparison_exclusion` set (or descendants). Index date = first visit. Age at index within bounds. |
| `03_lab_measurements.sql` | `lab_measurements` | Measurements in each analyte's concept set. Kept only if recorded in a listed unit, converted to the canonical unit, and within the observation period and optional index window. |
| `04_patient_features.sql` | `patient_features` | Per-person median of each analyte, age at index, sex (`is_male`, unknown → NULL), and completeness counts. |
| `05_completeness_selection.sql` | `analysis_dataset` | Top `n_per_cohort` persons per cohort by total qualifying measurement count (ties → lower `person_id`). |

## Inputs created by `omop_mdd.extract`

| Table | Source | Contents |
|---|---|---|
| `concept_set_member(concept_set, concept_id)` | `config/concept_sets.yaml` → `conditions` | Root concepts. Descendants are added through `concept_ancestor`. |
| `lab_concept(analyte, concept_id)` | `config/concept_sets.yaml` → `labs` | One concept per analyte. |
| `unit_conversion(analyte, unit_concept_id, multiplier, offset)` | `config/concept_sets.yaml` → `labs` | Canonical unit (×1 + 0) and any compatible alternate unit. |
| `analysis_params` | `config/analysis.yaml` → `cohort` | Age bounds, cohort size, lab window. |

Every clinical and unit concept ID in the configuration is **synthetic** (≥ 2,000,000,000). The only real concept IDs are 8507/8532 (gender) and 0 ("No matching concept").

## Decisions still required before use on a real OMOP CDM

None of these is resolved here. The synthetic configuration only lets the SQL run.

1. **Depression concept set.** Which standard concept(s) and vocabularies define the case cohort, and whether all descendants apply.
2. **Comparison-cohort exclusions.** Which diagnoses, and possibly medications, count as "depression-related."
3. **Index dates.** Cases use the first qualifying diagnosis. Comparison persons use their first visit in an observation period. Alternatives include a randomly selected or matched visit date, and the choice affects age at index.
4. **Age rule.** Age at index date, applied identically to both cohorts.
5. **Laboratory concept sets.** Real LOINC-based concept sets per analyte.
6. **Units.** The accepted units and conversion factors per analyte, and how unmapped units are handled.
7. **Observation window.** Unbounded by default (`null`). A window relative to the index date determines what the analysis can say about timing.
8. **Completeness rule.** Total measurement count (used here) vs. distinct analytes, and whether comparators should be matched on healthcare use.

## Running on Databricks (not tested)

The SQL uses DuckDB syntax. Equivalents that would be needed on Databricks SQL:

| DuckDB | Databricks SQL |
|---|---|
| `date_diff('day', a, b)` | `datediff(b, a)` |
| `MEDIAN(x) FILTER (WHERE …)` | `percentile(CASE WHEN … THEN x END, 0.5)` or `median(…)` |
| `date - INTEGER` | `date_sub(date, n)` |
| `SELECT r.* EXCLUDE (col)` | `SELECT r.* EXCEPT (col)` |
| `CREATE OR REPLACE TABLE` | same, or `CREATE OR REPLACE TEMP VIEW` |

These translations have not been executed on Databricks.
